# 科研工作流介绍

日期：2026-10-04

## 一句话

这是一套把「做一篇论文」从一串临时决定，改造成一条**有状态、有 gate、有证据、
可回退的流水线**的个人科研工作流。主路径是 LaTeX + BibTeX，模板库固定一份，
每篇论文派生一个独立目录；每个阶段都有明确的通过条件，凡能机械判定的检查都写成
确定性脚本，需要模型判断的环节则让执行与评审分开。

它真正的产品不是论文，而是**一篇论文的全部决策与证据的可审计记录**。

## 二、它解决的是什么问题

| 科研里的老问题 | 工作流的对应机制 |
| --- | --- |
| 结论和证据脱节，过两周说不清数字从哪来 | 数字行内标记 + 源值机械比对 |
| 引用没核验，正文出现悬空键 | 引用台账 + DOI 核验 + 悬空引用检测 |
| 复现失败，打包才发现缺文件缺参数 | 运行日志 + 来源登记 + 复现包真实重跑 |
| 版本混乱，`final-final` 满天飞 | git tag 快照 + 任意两版真实 diff |
| 最后一刻临时加实验，主线崩掉 | 倒排时间表 + T-30 后冻结新实验 |
| 自动提醒变成噪声，很快被全部忽略 | 默认安静，无实质变化不通知 |
| 自查有系统盲区 | gate 节点换独立模型评审 |
| 中断后回不到原位 | `ccfa.yaml` 状态机 + 回退留痕 |

## 三、三类核心资产

整个工作流只依赖三样东西，其余都是围绕它们的外围能力。

**1. 状态**
`ccfa.yaml` 是唯一的状态真相：当前 stage、gate、更新时间和完整的推进/回退历史。
任何阶段中断后，凭这个文件加目录内容就能判断「现在在哪、下一步缺什么」。

**2. 判据**
`tools/ccfa/stages.py` 是唯一的状态机定义，由此生成会议与期刊两套 checklist。
每个 stage 对应一个 gate，例如 `results-ready` 要求每个 claim 都能指到具体数值，
`submission-check` 要求复现包在干净环境真实重跑成功。

**3. 证据**
所有结论落在文件上：引用台账、数据来源登记、运行日志、图表 manifest、
复核报告、复现包。判据检查的是文件，不是对话记录，也不是模型的自述。

## 四、一篇论文的生命周期

### 派生

一条命令从模板库派生出完整目录，写入初始 `ccfa.yaml`，不留下半成品：

```powershell
scripts/new-paper.ps1 my-paper `
    --venue NeurIPS --year 2027 --mode conference --title "My Paper"
```

### 推进

会议模式：

```
idea -> grounded -> data-ready -> experiment-design -> experiments-running
     -> results-ready -> writing -> internal-review -> submission-check
     -> submitted -> rebuttal -> camera-ready -> archived
```

期刊模式前十个阶段共用，尾部换成：

```
submitted -> major-revision -> response-letter -> resubmitted -> accepted -> archived
```

回退被允许，但必须记录：从哪退到哪、触发事实是什么、哪些产物仍有效、哪些作废。

### 倒排

会议以 deadline 为锚点，脚本检查 T-90 到 T-1 八个节点与 gate 缺口。
T-30 之后不接受新实验这条是硬规则，脚本会扫描运行日志并在越界时报错。

### 归档

终稿、复现包、来源文档、评审记录一并落库；`research-version` 建立可对比的版本标签。

## 五、六个核心机制

### 1. 确定性工具

核心是十五个工具，覆盖引用核验、数字溯源、数据来源、运行日志、复现打包、
LaTeX 检查、版本快照、终稿检查、摩擦记录，以及人工证明/引用语义/图表语义复核、
人工编码一致性、新颖性审计、统计设计、治理/伦理检查和复现环境检查；连同状态、
文献、记忆、编排类工具，共 25 个 CLI 入口、1074 条工具侧测试。

所有工具遵守同一份契约：输入是路径或 stage 名，不读对话历史；机器可读 JSON
到 stdout，人读摘要到 stderr；退出码 `0` 通过、`1` 发现问题、`2` 工具自身出错；
检查类只读且幂等，写盘类原子写、不覆盖。`1` 与 `2` 必须分开，把「工具坏了」
混进「检查通过」，比检查失效更危险。

### 2. 证据链

**数字**：正文里写成 `\dataval{<源文件>:<键路径>}{<显示值>}`，编译时渲染为显示值，
脚本独立按路径回源核对。按显示精度推隐含舍入容差，所以正文写 `0.143` 而源值是
`0.142857...` 不会误报。指不到源的 claim 不允许标为 supported。

**图表**：每张交付图在 `figures/manifest.yaml` 里记录来源 run、源数据、生成脚本与
脚本哈希。交付图必须由脚本生成；确需手工修图的，必须写明改了什么。`data/figure-support.yaml`
再要求每张交付图有一条具名人工判断：这张图是否真的展示了正文用它所主张的结论。

**引用**：条目来自检索期核验过的台账，检查 DOI 与悬空引用。

**证明与语义**：`data/proof-audit.yaml` 要求每个 theorem/proposition/lemma/
corollary 都有具名人类复核记录；`data/citation-support.yaml` 要求受保护章节的
每个 `\cite{}` 都有一条人类「这句话是否真的被这篇文献支撑」的记录。脚本不判断
数学或语义本身，只强制这些判断有人做过、可追责、可复核。`data/figure-support.yaml`
把同一标准套到图表上：每张证据图都要绑定 claim 与正文原句，并留下具名判断。

**新颖性、统计与治理**：`data/novelty-audit.yaml` 强制检索范围/日期、≥3 篇近邻与
逐 claim 差异；`data/statistics-plan.yaml` 强制 alpha、功效、样本量、多重比较、
种子、停止规则与缺失数据处理；`data/governance.yaml` 强制署名/贡献、COI、伦理与
许可、AI 使用、查重、双用途与负责任披露；`data/repro-environment.yaml` 强制
requirements、lockfile 哈希和系统工具版本证据。它们同样只检查结构化声明，不保证结论正确。

**运行**：一次运行一个文件，失败也留档，不得静默重试到成功。

**复现**：打包后在新建环境里真实重跑，而不是只看文件是否齐全。

### 3. 执行与评审分离

gate 关键节点换独立会话与更大模型评审，避免同模型自查的系统盲区。
本机配置是执行用 `deepseek-v4-flash`、评审用 `deepseek-v4-pro`。
跨族评审列为可选升级，并如实标注同族评审的局限。`--allow-same-family`
现在必须同时给 `--override-reason`，原因写入评审记录；`check
--strict-cross-family` 会把任何同族 override 报成 problem。

### 4. 记忆

选题记忆避免重复自己；dead-end 记忆记录走不通的路线，并留一个 `reopen_if` 字段，
防止反重复机制误伤本来可行的方向。文献库用 SQLite FTS5 全文检索，中文走 `trigram`。

### 5. 自动化

文献监控、里程碑提醒、阶段推进、实验队列四类。统一策略是「没有实质变化就不通知」，
且只做信息收集与提醒，不修改正文、不自动推进 stage。实际挂载需明确确认。

### 6. 论文工作台

本地 PySide6 桌面壳，把「项目 → 阶段 → 检查 → 设置」做成界面，并给聊天模型开放
白名单工具。写操作必须过确认弹窗；调用日志只记参数哈希与结果，不记明文与密钥；
任意命令执行不暴露给模型。

## 六、它能保证什么

- 状态可恢复：中断后凭状态文件与目录就能回到原位。
- 证据可指认：正文关键数字、图表、引用都能指回具体文件。
- 失败不消失：失败的运行与检查留档，不被重试掩盖。
- 结构不出错：悬空引用、缺失图片、未解析标记、字节格式不符能机械检出。
- 人工复核不缺失：定理类环境与受保护引用必须有具名人类复核记录，
  否则 `internal-review` 不能通过。
- 过程可审计：每次推进、回退、评审、运行都有记录。
- 提醒不泛滥：没有实质变化就不打扰。

## 七、它不能保证什么

这一节是这套工作流最重要的部分。它验证的是**内部一致性**，不是**外部真实性**。

- 不保证结论正确：数字对得上源文件，不代表从源数据推出该结论的逻辑成立。
- 不保证证明成立：它能查引用、图表、编译和数字，查不出一条数学证明是否漏了条件。
- 不保证引用真的支撑论断：DOI 存在不等于这篇文献支持这句话。
- 不保证复现数值：当前验证是「脚本能在干净环境重算出汇总值」，不等于从原始数据重建全部结果。
- 不保证评审独立：默认评审与执行同属一个模型家族，同族评审弱于真正的跨族或人工评审。
- 不保证选题新颖：三篇最近邻是一个起点，不是充分的 novelty 证明。
- 不保证统计设计正确：有种子与置信区间，不等于有效功效分析或恰当的多重比较校正。
- 治理只做完整性 gate：署名/贡献、COI、伦理审查、数据许可、AI 使用、查重、双用途与负责任披露由 `data/governance.yaml` 强制留痕，但脚本不验证声明本身是否真实。

这不是自谦，而是一条已经被验证的边界。示例论文 `rag-attack-defense` 在流程内全部
gate 零问题通过：引用、数字、图表、LaTeX、运行日志、来源、复现包、跨模型评审逐项通过。
但随后一份外部 CSF 评审仍然指出核心命题 Proposition 4 的证明不成立，理由是它假设了
「分离防御无法阻止注入指令生效」，而这恰恰是这类防御要做的事。外部评分从 4.8 升到 6.3，
结论是 major revision / borderline，而不是可提交。

流程把内部一致性做到了零问题，却没能发现一个实质性的证明缺陷。这正是边界：
**gate 通过只说明案卷齐了，不说明案子赢了。**

v6 补丁把证明复核、引用语义支持与图表语义支持变成强制人工台账，但台账只证明
「有人做过判断」，不证明判断正确；数学证明的最终正确性仍要靠外部数学专家，
语义支撑与图-结论一致性的最终判断仍要靠领域专家。

## 九、怎么开始

```powershell
cd <仓库根>
python -m venv tools/.venv
& tools/.venv/Scripts/python.exe -m pip install -r tools/requirements.txt
$env:PYTHONPATH = (Resolve-Path tools).Path
& tools/.venv/Scripts/python.exe -m unittest discover -s tools/tests -t tools -v
```

派生新论文：

```powershell
scripts/new-paper.ps1 my-paper `
    --venue NeurIPS --year 2027 --mode conference --title "My Paper"
```

之后按 `checklists/conference.md` 或 `checklists/journal.md` 推进，
用 `scripts/milestones.ps1 due` 查看倒排节点与 gate 缺口。

目录约定与命令速查见仓库根 `README.md`，架构与接口契约见
`docs/design/2026-10-03-research-workflow-design.md`。
