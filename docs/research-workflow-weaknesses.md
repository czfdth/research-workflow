# 科研工作流缺点总结

日期：2026-10-04

## 一句话结论

这套工作流的**工程完成度很高，验证真实性很低**。它能保证过程可审计、状态可恢复、
失败不消失；它不能保证结论正确、证明成立、引用支撑论断。前者已经做到接近极致，
后者几乎是空白。

## 三个根因

**根因一：验证天花板。**
能机械判定的东西（引用是否悬空、数字是否对源、图片字节是否合规、编译是否通过）
被做成确定性 gate；决定论文成败的东西（证明是否成立、贡献是否成立、引用是否真的
支撑这句话、统计设计是否正确）没有任何 gate。示例论文九项检查全绿，外部评审仍
指出核心命题 Proposition 4 的证明不成立。gate 通过只说明案卷齐了，不说明案子赢了。

**根因二：独立性与人工验证不足。**
编码可靠性至今只有模型辅助审计，人工双编码尚未执行；已完成的那次模型互编码一致率
很低（capability 1/9、κ=0.0886；utility 2/9、κ=-0.0328）。跨族评审的 gate 已经
建好，但本机没有不同 family 的 provider，实际只能同族评审或显式 override。

**根因三：覆盖与信任边界由自己定义。**
哪些数字必须绑定由 `data/claims.yaml` 自己声明；复现包不声明依赖；实验与构建的
区分靠 `declared_purpose` 自报；跨族判定可被本机改写 JSON 伪造。所有边界的松紧
都取决于使用者自己的诚实程度。

## 可审计性偏置

第 1 至 5 条合起来指向同一个风险：系统奖励「可检查」，于是精力流向可检查的部分。
数字绑定、覆盖率报告、manifest 哈希、评审轮次都能产出漂亮的指标，而证明是否成立、
编码是否可靠、贡献是否真实，恰恰是无法用脚本打勾的部分。指标替代了目标。

最直观的证据是：这篇论文跑了 12 轮内部评审，修掉的是表格不同步、编码口径不一致、
报告自指循环这类一致性问题；真正的证明缺陷是外部人类评审发现的。流程把「案卷整齐」
做到满分，却没让论文更接近「结论正确」。

## 已经修掉的（截至 2026-10-04）

- 论文目录现在是独立 git 仓库，派生时自动 `git init` 并做初始提交。
- 引用台账要求抓取证据、正文哈希与标题匹配，不再接受手写 `verified`。
- `queue.py` 增加了 Docker 沙箱、GPU 秒预算与停滞看门狗。
- claims policy 把 abstract、contributions、findings 的数字纳入强制覆盖（19/19）。
- 跨族评审默认拒绝写入 pass，并对 stale 评审输入报错。
- 证据变化时工作流会自行从 `submission-check` 回滚到 `internal-review` 并作废 stale 评审。
- **E72–E74 真实性 gate**：`human-coding` 计算人工双编码一致率与 κ/CI；
  `argument-audit` 要求具名人类证明复核与引用语义支持（含 `claim_text`/`source_path`/
  `support_quote` 三元核对）；同族评审 override 必须写明理由并被 `--strict-cross-family`
  报出。
- **E75–E78 治理/统计/新颖性/复现环境**：`novelty`（≥2 数据库、≥3 近邻、逐 claim
  差异、禁止「没人做过」式表述）、`statistics`（alpha、功效、样本量、多重比较、
  停止规则、缺失数据处理）、`governance`（署名/贡献、COI、伦理与许可、AI 使用、
  查重、双用途与披露）、`repro-env`（requirements、lockfile 哈希、系统工具版本证据）。
- **E79 图表语义支持**：`argument-audit` 新增第三张台账 `data/figure-support.yaml`，
  每张交付图必须有具名人工判断，绑定 claim id 与正文原句；`contradicts`/`irrelevant`
  是 problem，`partial` 是 advisory；非证据图必须写理由。

**仍未闭合（都是「人」的问题，不是工具的问题）：** 示例论文自身的人工双编码尚未执行；
本机仍没有第二个 family 的 provider，跨族评审只能靠异常 override；证明正确性、
引用语义与图-结论一致性的最终判断仍依赖外部专家。工具现在保证「这些判断必须有人
做过、可追责、可复核」，不保证「判断正确」。

## 优先修的三条

1. **补人工验证**：执行 v2 人工编码包，报告一致率与 κ 的置信区间，并据此判断编码
   手册是否可用；不可用就先修手册，而不是先写论文。（工具已就绪：`scripts/human-coding.ps1`。）
2. **接入真正的跨族评审**：配置一个不同 family 的 provider，让默认路径能过 gate；
   把 override 限制为异常路径而不是常规做法。（工具已就绪，缺的是 provider 配置。）
3. **执行已建的三道语义复核**：给证明、引用与图表留下具名人工记录
   （`scripts/argument-audit.ps1` 会在缺失时退 1）。工具已就绪，剩余的是真正去复核。
